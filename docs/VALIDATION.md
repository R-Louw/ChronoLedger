# Validation

## Hyprland development environment

The owner uses Hyprland and continues other work while Codex develops. Tiling may allocate half-screen, quarter-screen, or another size instead of ChronoLedger's requested/default dimensions. This sizing alone is expected compositor behavior. Evaluate the UI within its actual allocation; investigate genuine clipping, overlap, or unusable controls.

If a check needs exclusive screen space or additional windows arranged by the owner (such as one or two terminals), ask for that setup and explain why. Preserve ongoing work and the current session. Continue independent tasks while waiting. Never close a production instance to make a test convenient; use isolated temporary data and application identity.

Run `./tools/check` after every change. Run `./tools/check memory` for ownership, persistence, or teardown changes covered by the deterministic targets. This enables ASan, UBSan, and leak detection. If the environment cannot run LeakSanitizer, record that limitation explicitly; disabling leak detection only validates ASan/UBSan, not leaks.

The core target covers malformed-input preservation, strict JSON boundaries, schemas 1–6 migrating to schema 7, fractional pause/switch/save/expiry arithmetic, maximum integer durations, completed-index invalidation after deletion and copying, 10,000-task snapshots, Calibration bounds and hit regions at density boundaries, stacked Focus content/action clearance, and bounded scene-history retirement and elapsed-time decay. The controller target uses completed GTK dialog tasks and retained GObjects to cover recovery mutation blocking, failed replacement rollback, explicit import, preference preservation, and cancellation versus real dialog errors. Neither target creates native windows or exercises GL context teardown.

For display-backed checks, keep the production session running. Setting `CHRONOLEDGER_FILE` selects a non-unique development instance so activation cannot be forwarded to the personal instance. Use a temporary ledger:

```sh
validation_dir=$(mktemp -d)
CHRONOLEDGER_FILE="$validation_dir/ledger.json" ./build-agent/chronoledger
```

For renderer-loss lifecycle changes, use a development-only harness on a real display: start an allocation, make the GL area current before releasing its renderer resources, refresh power policy, and keep the main loop running. Verify that the timer checkpoints and expires without a renderer, then close with a pending chooser. Run this harness with ASan/UBSan as well as a normal build. Do not add fault-injection switches or test callbacks to production code. Check both desktop GL and GLES when changing shader or context behavior; a single successful driver run does not establish portability.

For routines, test interval/daily/scheduled-confirmation creation, title and schedule editing, enable/disable, acknowledgment and deletion; inspect long titles at the minimum supported allocation. Acknowledge after several missed intervals and verify exactly one next due timestamp. Restart with an overdue routine and with a disabled routine. Check F1–F4 while editing and verify digits remain ordinary text. Close/reopen with each profile, manual sliders, palette and AA changes, and verify selected tab restoration. Recovery close must preserve malformed bytes and import must retain local routines and preferences.

### Separate native chooser lifecycle correction — 2026-11-16

The recorded actual-executable, GTK-only and ASan failures were reused. Upstream GTK 4.24.1 [window export completion](https://raw.githubusercontent.com/GNOME/gtk/4.24.1/gtk/gtkwindow.c), [file-dialog cancellation](https://raw.githubusercontent.com/GNOME/gtk/4.24.1/gtk/gtkfiledialog.c) and [native portal hide/cleanup](https://raw.githubusercontent.com/GNOME/gtk/4.24.1/gtk/gtkfilechoosernativeportal.c) explain why a retained window reference is insufficient, and why cancelling then immediately destroying the parent is unsafe. The [public file-dialog API](https://docs.gtk.org/gtk4/method.FileDialog.open.html) offers completion/cancellation, with no initialization-readiness barrier. This is upstream-code analysis, not a claim that an upstream fix/version has been identified.

The application now allows one pending native chooser, coalesces parent close requests while keeping its surface realized, consumes the native result and retries ordinary save/close. Late selections are discarded. Dismiss or complete the chooser to finish closing; it is intentionally not force-cancelled during initialization. A nonresponding native service can delay closure. No deadline, parentless chooser, deprecated replacement API, private GTK call, service change or rendering change was added. Pending state remains window-owned/main-thread; callbacks still retain the window and resolve its object data. Timer/checkpoint maintenance continues while close is deferred. The original CPU, appearance and cadence results above remain valid and were not repeated: this correction affects pending-chooser shutdown only.

[The reproducible display observer/runner](../tools/chooser-study/README.md) launches the actual executable with temporary ledgers/XDG directories and `.Development` identity, using the existing session bus. It targets Ctrl+I/Ctrl+E and uniquely titled real native chooser windows. An initialization close is queued at the original high idle priority and asserts zero portal chooser requests before closing on Wayland, proving it precedes parent-export completion. Presented cases wait for the native window. Both repeat close, verify the same parent surface remains alive, then dismiss/select through the real chooser. Completion must call GTK's finish function, clear pending state, stop both scheduling sources, unrealize the GL area, release the window/GL area/dialog/GTask (and selected GFile), and exit 0 with no test windows left. Merely surviving an observation timeout does not pass.
